# OlbosTrade Live Audit — 2026-06-23

Audit triggered by operator report (IBKR + Hetzner deployment):

1. "App is designed for options but I only see equity trades — no options activity."
2. "The marquee/header market data looks simulated — stocks are down but show green
   and the percentage never changes."
3. "I don't see Journal/execution entries for equity."
4. "Audit the entire app."

This document records what was found and what was fixed in this pass. Items marked
**FIXED** are changed in this commit; items marked **OPEN** are recommendations.

---

## 1. Why no options ever traded — **FIXED** (root cause)

**The marquee data is NOT simulated and options generation was working — but every
options order was submitted at a price that could never fill.**

The options scan (`main.py::_run_options_scan`) computes the spread net credit in
**per-contract dollars**:

```python
net_credit = round((short_px - long_px) * 100, 2)   # e.g. $150 for a $1.50 spread
```

The execution path (`trade_desk.py::_execute_signal`, options branch) then passed
that dollar figure straight through as the broker limit price:

```python
limit_px = Decimal(str(round(credit * aggression, 2)))   # 150.00
```

IBKR option/combo limit prices are **per-share** (the broker applies the ×100
multiplier itself). Submitting a BUY combo at a net price of `-150` asks to *receive
$150 of credit per spread* on a spread actually worth ~$1.50 — so the order sat
unfilled, hit the retry/cancel path, and returned `cancelled`. No fill → no recorded
options trade → the blotter and journal only ever showed equities.

**Fix:** convert the per-contract dollar credit back to a per-share net price before
building the order, and store the per-share credit on the trade so exit P&L is
consistent:

```python
credit_per_share = float(credit) / 100.0          # 1.50
limit_px = Decimal(str(round(credit_per_share * aggression, 2)))
...
entry_credit = credit_per_share                    # stored per-share
```

Files: `backend/app/api/routes/trade_desk.py`.

### Related items for options
- **Risk-based sizing for options — FIXED.** `_run_options_scan` now sizes each spread
  via `RiskManager.calculate_position_size` off portfolio value, the spread's max loss,
  the active trading mode's `risk_per_trade_pct`, and the regime's
  `options_size_multiplier` — the same machinery the equity path uses. A spread that
  sizes to 0 contracts is skipped instead of forced to 1.
- **AI signal score / min-confidence gate on options — FIXED.** The options scan now
  builds `SignalFeatures` (IV rank, VIX, RSI/ADX from the regime, DTE, short-strike
  delta, credit-to-width, etc.) and runs `SignalScorer.score_async`. Spreads that the
  scorer rejects are no longer routed to execution; the real `signal_score` is recorded
  on the trade instead of the previous hardcoded `0`.
- **Black-Scholes credit vs. real NBBO — FIXED.** The scan now prices the selected
  spread off the **live IBKR chain** (`_live_spread_quote`): it snaps to the nearest
  available strikes, takes the bid/ask mid of each leg, and uses the real net credit
  and short-leg delta. Black-Scholes remains the fallback when no quote is available
  (e.g. no options market-data subscription — bid/ask come back empty), so the path
  works with or without a live feed. The chosen source is recorded on the signal as
  `credit_source` (`live_chain` | `black_scholes`).
- Options only scan **SPY**, once per 30 min; equities scan a 13-symbol watchlist
  every 15 min. Expect equities to dominate volume regardless.

## 2. Header marquee always green / % never changes — **FIXED**

Data source is real (yfinance), **not simulated**. The bug was in the change-%
calculation in `market_data.py::_yfinance_snapshot`.

During/after market open, yfinance's daily history includes **today's in-progress bar
as the last row**. The code used that row as the previous close:

```python
prev_close = float(daily_closes.iloc[-1]) if intra.empty else float(daily_closes.iloc[-1])
# (both branches identical — today's bar)
```

So `prev_close ≈ last`, making `change_pct ≈ 0.00%` for every symbol while the market
is open. The ticker color is `pct >= 0 ? green : red`, and `0 >= 0` → **green** — which
is exactly "down stocks shown green with an unchanging 0%."

**Fix:** use the previous *completed* session (`iloc[-2]`) as the reference whenever a
prior session exists.

File: `backend/app/api/routes/market_data.py`.

## 3. Equity P&L was mis-modeled (sign + ×100 multiplier) — **FIXED**

Equity trades *were* being recorded to the DB and journal (every fill calls
`trade_recorder.record_fill`, which writes a `Trade` row + `JournalEntry` stub). If the
journal looked empty for equities it was because trades were recorded as **open** and
P&L only appears on close — and the close-side math was wrong:

`record_exit` used the credit-spread formula for everything:

```python
pnl = (credit - cost_to_close) * qty * 100
```

For an equity **long** that bought at 100 and closed at 110 this produced
`(100 - 110) * qty * 100 = -1000·qty` — wrong **sign** (a winner booked as a loser)
**and** wrong **magnitude** (equities have no ×100 contract multiplier).

**Fix:**
- Direction is now encoded at entry (`equity_long` / `equity_short`, derived from the
  signal's BUY/SELL action) in the `Trade.spread_type` field — no schema migration
  required.
- `record_exit` detects equity, uses multiplier **1**, and applies the correct sign:
  long = `exit − entry`, short = `entry − exit`. Options keep multiplier **100** with
  the credit-spread convention.

Files: `backend/app/api/routes/trade_desk.py`, `backend/app/services/trade_recorder.py`.

P&L unit convention is now consistent: `credit_received` is stored **per-share /
per-contract-unit** for both asset classes, and the multiplier is applied once at exit.

## Second pass — additional fixes

- **Equity bracket orders were silently dropped — FIXED.**
  `ibkr_client.place_equity_order` set `order.takeProfitPrice` / `order.stopLossPrice`
  on a plain `MarketOrder`/`LimitOrder`; ib_insync ignores those attributes, so
  protective exits never reached IBKR. Replaced with a real bracket: a parent entry
  order plus OCO child take-profit (LMT) and stop-loss (STP) orders linked via
  `parentId`, transmitted as a group. Also wired the trade plan's `target_price`
  through the execution path (it was never passed to the broker).
- **Portfolio Greeks misclassified equities as options — FIXED.**
  `_update_portfolio_greeks` keyed on `option_type`, but the broker client tags equity
  positions with a placeholder `option_type="call"` and `strike=0`. Equities were
  therefore added as options with zero Greeks, dropping their delta from the net.
  Detection now uses the `strike==0` sentinel; equity delta is included again.

## Third pass — additional fixes

- **Auto-close fabricated $0 P&L — FIXED.** `_poll_fills` previously (a) averaged
  *all-time* executions for a symbol — mixing the opening fill into the exit — and
  (b) fell back to `exit = entry` (P&L ≈ 0) when no execution was found, booking a fake
  neutral close that polluted win-rate / loss-limit math. Now:
  - `_compute_exit_price` reconstructs cost-to-close from only the **closing-side**
    fills that occurred **at/after entry**, weighted by shares — equity by side
    (long→SLD, short→BOT), options by matching each leg's strike/right (buy back short,
    sell long).
  - When a reliable exit price can't be determined, the trade is **held open and
    retried** for a grace window (`CLOSE_GRACE_SECONDS=300`); only then is it closed
    with **unknown P&L** (`pnl=NULL`, `record_close_unknown`) plus a CRITICAL alert.
    Guardrail/journal math filters on `pnl IS NOT NULL`, so unknown closes are excluded
    rather than counted as a $0 trade.
- **`trades_today` inconsistency — FIXED.** Both `trade_desk._fetch_portfolio_state`
  (used by the daily-cap guardrail) and `main.guardrail_status` (status panel) now count
  every trade **entered today** regardless of open/closed status. Previously one counted
  open-entered-today and the other closed-exited-today, so the cap and the panel could
  disagree and a same-day round-trip escaped the cap.

## Other findings (OPEN — recommendations, not changed)

- **Options exit reconstruction depends on execution history availability.**
  `reqExecutions` only returns a limited recent window; a spread closed long ago (or via
  expiry/assignment, which produce no closing execution) will fall through to an unknown
  close. That is the safe outcome (no fabricated P&L) but means some realized P&L needs
  manual entry. A position-level cost-basis feed would close this gap.
- **Market data is delayed.** Header/snapshots/regime all use yfinance (15-min delayed
  intraday, last close otherwise) and IBKR is set to delayed-frozen (type 4). This is by
  design (no paid subscription) but means nothing in the UI is real-time.
- **Options Flow module is idle by default** (`options_flow_enabled=false`) because
  live OPRA tick data requires a paid subscription. The "Flow" page will be empty unless
  enabled or run in demo mode.

## Second full audit (post-deploy pass)

Reviewed the execution/risk/broker internals, signal generation, and pricing math
that the first pass hadn't covered. Findings and fixes:

- **Kill switch did not survive restart — FIXED (safety).** The docstring claimed
  engaged state persisted, but `_engaged` was in-memory only and nothing rehydrated
  it on startup — so a restart (or the watchdog/daily ops) silently re-enabled
  trading after the switch had been engaged. Added `KillSwitch.rehydrate()` (reads
  the most recent `kill_switch` / `kill_switch_reset` GuardrailEvent and re-engages
  if the latest is an engage), called it in startup, and made `reset()` write a
  `kill_switch_reset` event so the engage/reset history is complete.
- **Equity signals skewed bearish — FIXED (signal quality).** The scan fetched only
  120 bars but EMA200 needs 200, so `above_ema200` was always False — adding a
  systematic bear point and removing a bull point on every symbol (the cause of the
  near-all-SELL signals seen live). Bumped the scan to 250 bars so EMA200 is valid.
- **`paper_mode` mis-reported — FIXED.** Detection only recognized ports 4002/7497,
  so the containerized gateway on 4004 showed `paper_mode:false` even though the
  account is paper. Now keys off `IBKR_TRADING_MODE` plus the live-port set
  (4001/7496), so custom container ports report correctly.
- **`/api/market/broker` status lied — FIXED.** It returned `"connected"` whenever
  the broker object existed, even while the socket was down (it said connected
  through the whole Gateway outage). Now reports the real `ib.isConnected()` state.

### Open (noted, not changed)
- **No API authentication.** Every endpoint — including `POST /kill-switch`,
  `/execution-mode`, and `/manual-trade` — is unauthenticated. Safe only because the
  backend isn't published on a host port (internal docker network + Caddy). If Caddy
  ever exposes it on a public route, anyone could control trading. `settings.secret_key`
  exists but is unused; recommend gating mutating endpoints behind it.
- **Dormant duplicate execution path.** `PaperTrader` + `ExecutionDispatcher` +
  `multi_leg_strategy` are a second, fuller execution stack that the live autopilot
  flow (`_run_*_scan` → `handle_signal` → `_execute_signal`) does not use. Only the
  backtester and the dormant PaperTrader reference them. Harmless but confusing —
  candidate for removal or consolidation.

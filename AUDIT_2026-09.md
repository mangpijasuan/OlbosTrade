## Items fixed this pass

### 1 · FastAPI `@app.on_event` deprecation — **FIXED**

**Severity:** P2 (no runtime effect today; will break on a future FastAPI major version and generates DeprecationWarning on every startup/test)

`app/main.py` used `@app.on_event("startup")` and `@app.on_event("shutdown")`, which FastAPI has deprecated in favour of the lifespan context-manager pattern since v0.95.

**Fix:** added `@asynccontextmanager async def lifespan(app)`, renamed the two event handlers to `_on_startup()` / `_on_shutdown()`, and passed `lifespan=lifespan` to `FastAPI(...)`. The startup and shutdown logic is unchanged; only the registration mechanism changed.

Files: `backend/app/main.py`.

### 2 · `RuntimeWarning: coroutine 'AsyncMockMixin._execute_mock_call' was never awaited` — **FIXED**

**Severity:** P3 (test warning only; no production effect)

`tests/test_trade_desk_routes.py::test_kill_switch_get_set` patched `kill_switch_service.reset` as a bare `AsyncMock()` with no configured return value. The production code calls `result.get("reset")` on the awaited result; when the mock returned a generic `MagicMock`, Python's mock machinery created a new unawaited coroutine object while resolving the `.get()` attribute, emitting the warning.

**Fix:** set `return_value={"reset": True}` on the reset mock and `return_value={}` on the engage mock so both return plain dicts — the types the production code expects.

Files: `backend/tests/test_trade_desk_routes.py`.

### 3 · `IBKRRequestCoordinator` worker tasks destroyed but pending in tests — **FIXED**

**Severity:** P3 (test noise only; no production effect — the production app runs a single event loop for its lifetime)

Every test that imports `ibkr_coordinator` (directly or transitively through `ibkr_client`) spawns the coordinator's worker tasks via `start()`. When the per-test event loop is torn down, those tasks are still waiting on their queues and produce:

```
Task was destroyed but it is pending!
task: <Task pending name='Task-N' coro=<IBKRRequestCoordinator._worker_loop() running at ibkr_coordinator.py:241>>
```

**Fix:** added `IBKRRequestCoordinator.stop()` — an async method that cancels all worker tasks and awaits them with `gather(..., return_exceptions=True)`. The app's `_on_shutdown()` now calls `ibkr_coordinator.stop()` so the coordinator is cleanly shut down on every graceful exit (both production and test teardown via the lifespan handler).

The existing `start()` per-loop detection logic is unchanged; `stop()` complements it for teardown.

Files: `backend/app/broker/ibkr_coordinator.py`, `backend/app/main.py`.

### 4 · `TRADING_POLICY.md` claimed "Options spreads are SPY-only" — **FIXED**

**Severity:** P3 (docs drift; no runtime effect)

The charter read:

> Options spreads are SPY-only today (the options spread engine is SPY-hardwired)

This was true at the June 2026 audit. Since then (commit `366273b` et al.) `_run_options_scan` was rewritten to scan the **full equity watchlist** (~59 symbols), rank candidates by quality score, and route the highest-scoring spread. The claim was false for several months.

**Fix:** updated the "Supported assets → Status" paragraph to reflect the current reality: the background options scanner covers the full watchlist and ranks candidates before execution.

Files: `TRADING_POLICY.md`.

### 5 · Vestigial `POST /api/equity/signals/{signal_id}/approve` — **FIXED**

**Severity:** P2 (dead code with a wrong invariant; was flagged open in every prior audit)

`equity.py:136` stamped `approved_at` on a signal in the in-memory `_recent_signals` list. This never triggered execution — it was a leftover from a pre-queue design. The frontend's real approval path (`CopilotQueue.tsx`, `TradeDesk.tsx`) calls `POST /api/trade-desk/approve/{id}` (which IS authenticated and does execute). Nothing in the frontend called the equity route.

**Fix:** removed the endpoint and the now-unused `timezone` import it was the sole consumer of.

Files: `backend/app/api/routes/equity.py`.

### 6 · `PUT /api/strategy/config` was a misleading no-op — **FIXED**

**Severity:** P2 (silent data contract lie: returned `{"updated": true}` for an update that changed nothing)

`strategy.py:43` returned `{"updated": True, "strategy": ..., "message": "Use /api/mode/set..."}` — claiming success while doing nothing. The endpoint existed as a shim for an older design where per-strategy toggles lived here; the real mechanism is the trading-mode system. The API client (`client.ts:167`) had an `updateStrategyConfig` function defined but it was never called from any frontend component.

**Fix:** the endpoint now returns HTTP 410 Gone with a clear redirect message. The `updateStrategyConfig` function was removed from `client.ts`.

Files: `backend/app/api/routes/strategy.py`, `frontend/src/api/client.ts`.

## Architecture health snapshot (current state)

### What is genuinely sound

- **Single execution path.** AUTOPILOT still routes exclusively through `_execute_signal` (kill switch → market hours → guardrails → frequency controller → strategy health → duplicate guard → sizing → portfolio gate → broker). No competing execution path.
- **Regime stabilizer.** Hysteresis on regime changes (3 consecutive readings to adopt; CRISIS is instant) prevents machine-speed strategy-hopping. Working correctly.
- **Kill-switch rehydration.** Survives restarts; tested.
- **Risk-limit constants unified.** `portfolio_greeks.py` imports from `RiskManager` — the duplication-by-coincidence gap closed in the prior pass is verified still closed.
- **Position identity.** `(underlying, asset_type)` keying is in place; duplicate-guard and reconciliation both use it.
- **Options pricing.** Live IBKR chain quotes used when available; Black-Scholes fallback documented and logged via `credit_source`.
- **P&L math.** Equity and options both use correct multipliers and direction conventions; verified in `test_batch4_recording.py`.
- **Live tenure guard.** Blocks live-capital execution until 90 days of paper history + 20 closed trades — tested.
- **API auth.** All trade-execution mutate routes carry `require_api_key`. `require_api_key` is a no-op when `SECRET_KEY` is not set (paper-only installs), so single-operator local installs are unaffected.
- **Account mode guard.** Startup verifies the IBKR gateway's account type matches `IBKR_TRADING_MODE`; fail-closed if unreadable.

### What is paper-safe but not yet live-capital-ready

- The `POST /api/mode/set` unauthenticated gap (above).
- No trained XGBoost model.
- `main.py` architectural debt (hard to audit the scheduler loop for new regressions).
